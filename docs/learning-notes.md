
# 商品検索アプリ 学習ノート

## 1. 開発を通じて学んだこと

今回、Next.js・React・TypeScriptを使用して、30件の商品データから商品名検索とカテゴリ絞り込みができるWebアプリを開発した。

主な学習内容は以下のとおり。

- 要件定義と画面設計
- Next.js・React・TypeScriptの基本
- コンポーネント設計とprops
- JSONによるデータ管理
- React Hooksによる状態管理
- 商品検索とAND検索の実装
- fetchによる非同期データ取得
- URLクエリと検索状態の同期
- エラー処理と再試行処理
- コード品質チェックと動作テスト
- Chrome DevToolsによる性能測定
- Claude Codeによるコードレビューと修正

今回の大きな学びは、コードを書く前に設計を行い、実装後は必ず検証することの重要性である。

## 2. 要件定義と画面設計

### 2.1 要件定義とは

システムに必要な機能や動作を、開発前に明確にする工程。

今回のアプリでは、次の仕様を決定した。

- 商品データは30件
- 商品名によるリアルタイム検索
- カテゴリは5種類
- 商品名とカテゴリはAND検索
- 初期状態では30件を表示
- 検索欄の初期値は空欄
- カテゴリの初期値は「すべて」
- 検索結果0件では専用メッセージを表示
- リセットすると検索条件とURLクエリを初期化
- 検索欄のクリアはキーワードのみ削除
- JSON取得中は読み込みメッセージを表示
- JSON取得エラー時には再読み込みボタンを表示
- 検索操作から画面更新まで100ms以内を目標とする

### 2.2 画面設計

縦型レイアウトを採用した。

画面の表示順序は以下のとおり。

1. アプリのタイトル
2. 商品名の検索フォーム
3. カテゴリ選択ボタン
4. 検索結果件数
5. 商品一覧テーブル

テーブルの表示項目は以下の4つ。

- 商品名
- カテゴリ
- 価格
- 在庫数

スマートフォンでは、表を横スクロールできる設計とした。

### 学んだこと

画面に何を表示するかだけでなく、ユーザーが操作したときに何が起きるかまで決めることが重要。

仕様を先に決めることで、実装途中の判断に迷いにくくなる。

## 3. Next.js・React・TypeScript

### 3.1 Next.js

Reactを使ってWebアプリを開発するためのフレームワーク。

今回使用した機能：

- App Routerによるページ構成
- page.tsxによるページ表示
- layout.tsxによる共通レイアウト
- 開発サーバー
- 本番ビルド
- useSearchParamsによるURLクエリ取得

### 3.2 React

画面をコンポーネントという部品に分けて構築するためのライブラリ。

ユーザーの操作によって状態が変わると、Reactが必要な部分を再描画する。

### 3.3 TypeScript

JavaScriptに型の仕組みを追加した言語。

商品データの型を定義したことで、データの構造を明確にできた。

```ts
export type Product = {
  id: number;
  name: string;
  category: ProductCategory;
  price: number;
  stock: number;
};
```

### 3.4 Server ComponentとClient Component

Server Component：
主にサーバー側で処理・描画を行うコンポーネント。

Client Component：
useStateやイベント処理など、ブラウザでの操作に必要な機能を使用できるコンポーネント。

今回のProductSearch.tsxでは、ファイルの先頭に以下を記述した。

```tsx
"use client";
```

### 学んだこと

Next.jsとReactは同じものではない。

Reactは画面を構築する仕組みで、Next.jsはReactを使ったアプリ開発に必要な機能を提供する。

また、TypeScriptの型定義によって、データの間違いを実行前に発見しやすくなる。

## 4. コンポーネント設計とprops

### 4.1 コンポーネントとは

画面を構成する再利用可能な部品。

今回のファイル構成：

| ファイル | 役割 |
|---|---|
| app/page.tsx | ページの表示 |
| components/ProductSearch.tsx | 検索画面全体の状態管理 |
| components/SearchForm.tsx | 商品名入力 |
| components/CategoryFilter.tsx | カテゴリ選択 |
| components/ProductTable.tsx | 商品一覧表示 |
| lib/products.ts | 商品検索処理 |
| types/product.ts | 商品データの型 |
| public/products.json | 商品データ |
| scripts/test-filter.ts | 検索ロジックのテスト |

### 4.2 親コンポーネント

複数の子コンポーネントに必要な状態をまとめて管理する。

今回のProductSearch.tsxでは、検索キーワード、カテゴリ、商品データなどを管理した。

### 4.3 props（プロップス）

親コンポーネントから子コンポーネントへ、データや関数を渡す仕組み。

```tsx
<SearchForm
  query={query}
  onQueryChange={handleQueryChange}
/>
```

query：
現在の検索キーワードを渡す。

onQueryChange：
検索キーワードを変更するための関数を渡す。

### 4.4 イベントハンドラー

クリックや文字入力など、ユーザー操作が発生したときに実行する関数。

例：

- handleQueryChange
- handleCategoryChange
- handleReset
- handleRetry

### 学んだこと

画面を役割ごとに分割することで、コードを理解しやすくなる。

また、状態管理を親に集約することで、検索フォームとカテゴリ選択を連動させやすくなる。

## 6. React Hooksと状態管理

### 6.1 useState

画面の状態を管理するReact Hook。

今回使用した主な状態：

| 状態 | 役割 |
|---|---|
| products | 商品データ |
| query | 検索キーワード |
| category | 選択カテゴリ |
| loading | データ取得中か |
| error | 取得エラーの有無 |
| reloadCount | 再取得のきっかけ |

### 6.2 useEffect

外部データの取得など、Reactの描画後に外部システムとの同期を行うためのHook。

今回、商品データ取得時に使用した。

### 6.3 useCallback

関数の参照を再描画間で維持するためのHook。

当初はloadProductsをuseCallbackで定義していたが、コードレビュー後に取得処理をコンポーネントの外へ分離したため、不要になった。

### 6.4 依存配列

useEffectなどの再実行を制御する値の配列。

```tsx
[reloadCount]
```

reloadCountが変わると、商品取得処理が再実行される。

### 6.5 再レンダリング

Reactが状態の変更に応じて画面を更新すること。

### 学んだこと

状態が変更されるとReactが画面を更新する。

ただし、必要のない状態更新を増やすと、余分な再描画につながる可能性がある。

状態をどこで、いつ変更するかが重要である。

## 7. 商品検索とAND検索

### 7.1 filter()

配列から条件に一致するデータを取り出すメソッド。

### 7.2 includes()

文字列に指定した文字が含まれているか判定するメソッド。

### 7.3 AND検索

複数の条件をすべて満たす商品だけを抽出する処理。

例：

検索キーワード：マウス

カテゴリ：PC周辺機器

結果：両方の条件に一致する商品のみ表示する。

### 7.4 リアルタイム検索

キーボードで文字を入力すると、検索結果が即時に更新される仕組み。

今回、queryの状態更新に合わせてfilterProducts()を実行した。

### 学んだこと

検索処理をlib/products.tsに分離することで、画面表示とは独立してテストできる。

また、検索条件を組み合わせることで、ユーザーが必要な商品を絞り込める。

## 8. 非同期処理とfetch

### 8.1 fetch()

Web上のデータやJSONファイルを取得するためのJavaScriptの機能。

読み方：フェッチ

### 8.2 非同期処理

データ取得など、完了まで時間がかかる処理を待っている間に、他の処理を進められる仕組み。

### 8.3 async / await

非同期処理を順番に書きやすくする構文。

### 8.4 Promise

非同期処理の結果を表すオブジェクト。

### 8.5 then / catch / finally

then：
非同期処理が成功した場合に実行する。

catch：
非同期処理が失敗した場合に実行する。

finally：
成功・失敗にかかわらず、処理が完了したときに実行する。

### 8.6 cache: "no-store"

fetchでキャッシュを利用せずにデータを取得するための指定。

### 8.7 cleanup

不要になった非同期処理の結果が、後から画面に反映されないようにする後片付け。

今回、ignoreフラグを使用して古い取得結果を無視する処理を追加した。

### 学んだこと

データの取得処理とReactの状態更新を分けることで、コードの役割が明確になる。

また、データ取得に失敗した場合を想定したエラー処理が必要である。

## 10. エラー処理と解決履歴

### 10.1 作業フォルダの間違い

発生した問題：

Node.jsでproducts.jsonを確認しようとした際、ファイルが見つからないエラーが発生した。

原因：

ターミナルの現在位置がsearch-filterではなかった。

解決：

```powershell
cd search-filter
```

学び：

相対パスは、現在の作業フォルダを基準に解釈される。

コマンドを実行する前に作業場所を確認する必要がある。

### 10.2 JSXの閉じタグ重複

発生した問題：

SearchFormの後に余分な閉じタグを追加したことで構文エラーが発生した。

原因：

JSXのタグの開始と終了が対応していなかった。

解決：

不要な閉じタグを削除した。

学び：

JSXではタグの構造を正しく保つ必要がある。

### 10.3 useEffectの重複

発生した問題：

古いuseEffectを残したまま新しい取得処理を追加し、複数のエラーが発生した。

原因：

不要な関数・括弧が残っていた。

解決：

古いuseEffectと不要な閉じ括弧を削除した。

学び：

1つの構文エラーが複数のエラーを発生させることがある。

また、コードを置き換える際は、古い処理を残さないように注意する。

### 10.4 react-hooks/set-state-in-effect

発生した問題：

ESLintでreact-hooks/set-state-in-effectのエラーが1件発生した。

原因：

useEffectから呼び出した関数が、非同期処理を待つ前に状態更新を行っていた。

解決：

- fetchProducts()をコンポーネントの外へ分離
- Promiseのthen/catch/finallyで取得結果を処理
- reloadCountによる再試行を採用
- ignoreフラグによるcleanupを追加
- 不要なuseCallbackを削除

結果：

ESLintエラー0件。

学び：

エラーの原因は、必ずしもエラー表示された1行だけにあるとは限らない。

処理全体の構造を確認することが重要。

また、コードの修正前に一時コピーで検証すると、安全に修正方法を比較できる。

## 12. Chrome DevToolsと性能測定

### 12.1 Chrome DevTools

Chromeに搭載されている開発者向けの調査ツール。

今回Performanceタブを利用した。

### 12.2 INP

Interaction to Next Paintの略。

ユーザー操作に対する画面の応答性を評価する指標。

### 12.3 Input delay

操作が発生してからイベント処理が開始されるまでの待ち時間。

### 12.4 Processing duration

イベント処理にかかった時間。

### 12.5 Presentation delay

イベント処理後、次の画面描画までにかかった時間。

### 12.6 CLS

Cumulative Layout Shiftの略。

画面レイアウトの意図しないずれを評価する指標。

### 12.7 今回の測定

本番モードで以下の応答時間を確認した。

| イベント | 応答時間 |
|---|---|
| Pointer | 2.26ms |
| Pointer | 26.88ms |
| Keyboard | 23.81ms |
| Other | 6.73ms |
| Other | 19.11ms |
| Other | 8.31ms |

- 最大値：26.88ms
- INP：27ms
- CLS：0
- 目標：100ms以内

確認した6イベントは100ms以内だった。

ただし、各イベントと個々の検索操作の厳密な対応関係までは特定していない。

### 学んだこと

JavaScriptの処理時間だけでは、ユーザーが感じる画面の応答性を正しく判断できない。

入力から画面描画まで確認することが重要。

また、開発モードと本番モードでは性能に違いが出る可能性があるため、両方を確認すると理解が深まる。
