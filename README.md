# Search Filter App

## 1. プロジェクト概要

Next.jsを使用して、検索フォームとカテゴリ絞り込み機能を持つWebアプリを開発する学習プロジェクト。

**開発目的**

Webアプリの基本構造、データ取得、検索処理、URLによる検索状態の管理を理解し、自分で説明・実装できるようになること。

詳細な要件は、今後の要件定義で決定する。

## 2. 使用技術

| 技術 | 用途 |
|---|---|
| Next.js 16.4.3 | Webアプリの構築 |
| React | UIの構築 |
| TypeScript | プログラミング言語 |
| Tailwind CSS | スタイリング |
| JSON | サンプルデータの管理 |
| Git / GitHub | ソースコードのバージョン管理（予定） |
| Vercel | Webアプリの公開（予定） |

## 3. 開発環境

- OS：Windows 11
- エディター：Visual Studio Code
- ターミナル：PowerShell
- プロジェクト名：search-filter

### 起動手順

プロジェクトフォルダに移動する。

```powershell
cd search-filter
```

※すでにsearch-filterフォルダ内にいる場合は移動不要。

開発サーバーを起動する。

```powershell
npm run dev
```

ターミナルに表示されたLocalのURLをブラウザで開く。

例：http://localhost:3001

※ポート番号は起動環境によって異なる。

開発サーバーを停止する場合は、ターミナルで `Ctrl + C` を押す。

## 5. 要件定義

### 5.1 プロジェクトの目的

JSON形式の商品データ30件を使用し、商品名検索とカテゴリ絞り込みができるWebアプリを開発する。

検索条件をURLクエリに反映し、ページ再読み込み後やURL共有時にも同じ検索結果を再現できるようにする。

### 5.2 商品データの仕様

データ形式：JSON

データ件数：30件

カテゴリ：5種類（各6商品）

| 項目 | キー | データ型 | 内容 |
|---|---|---|---|
| 商品ID | id | number | 商品を識別する一意の番号 |
| 商品名 | name | string | 商品の名称 |
| カテゴリ | category | string | 商品の分類 |
| 価格 | price | number | 商品の価格（円） |
| 在庫数 | stock | number | 商品の在庫数量 |

**商品カテゴリ**

1. パソコン
2. PC周辺機器
3. スマートフォン
4. オーディオ
5. 家電

各カテゴリに6商品ずつ、合計30件のサンプルデータを用意する。

### 5.3 機能要件

**FR-01：商品データの取得・一覧表示**

- JSON形式の商品データを `fetch()` で取得する。
- 取得成功時に商品一覧を表示する。
- 初期状態では全30商品を表示する。

**FR-02：商品名のテキスト検索**

- 商品名を対象に検索できる。
- 入力した文字列を含む商品を表示する（部分一致）。
- 文字を入力するたびに検索結果をリアルタイム更新する。
- 検索欄が空の場合は、商品名による絞り込みを行わない。

**FR-03：カテゴリ絞り込み**

- タグ・ボタン方式を採用する。
- カテゴリは単一選択とする。
- 「すべて」を選択した場合はカテゴリで絞り込まない。
- カテゴリを変更すると検索結果を即時更新する。

**FR-04：複合検索**

- 商品名検索とカテゴリ絞り込みを組み合わせる。
- AND検索を採用する。
- 両方の条件が指定されている場合は、両方を満たす商品のみ表示する。

**FR-05：URLクエリとの連携**

- 検索キーワードを `q` に反映する。
- カテゴリの選択状態を `category` に反映する。
- 検索操作と同時にURLを更新する。
- ページ再読み込み後も検索条件を復元する。
- 検索条件を含むURLを共有すると、同じ検索結果を表示できる。
- 初期状態では検索条件のクエリを付けない。

URL例：

`/?q=マウス&category=accessories`

※カテゴリのURL用識別子はデータ設計時に確定する。

**FR-06：検索結果0件の表示**

- 該当商品が0件の場合は、空状態UIを表示する。
- 「該当する商品がありません」というメッセージを表示する。
- 検索条件をリセットするボタンを表示する。

**FR-07：検索条件のリセット**

- 検索キーワードを空欄に戻す。
- カテゴリを「すべて」に戻す。
- URLから `q` と `category` を削除する。
- 商品一覧に全30件を再表示する。

**FR-08：データ取得状態の表示**

- データ取得中は「商品データを読み込み中」と表示する。
- データ取得に失敗した場合は、エラーメッセージを表示する。
- エラー時には再読み込みボタンを表示し、データ取得を再試行できるようにする。
- データ取得エラーと検索結果0件は区別する。

### 5.4 非機能要件

**NFR-01：検索応答性能**

- 検索操作から画面の絞り込み結果が更新されるまで、100ms以内を目標とする。
- テキスト入力とカテゴリ選択の両方を計測する。
- 30件のデータを読み込んだ状態で検証する。
- ブラウザの開発者ツールなどを使用し、操作から画面更新までの時間を測定する。
- 計測条件・結果を「9. テスト・検証結果」に記録する。

**NFR-02：URLによる検索状態の再現性**

- URLの検索条件と画面の表示状態が一致すること。
- 再読み込み後も選択状態が保持されること。
- URLを別タブで開いても同じ検索結果が表示されること。

### 5.5 初期状態

| 項目 | 初期値 |
|---|---|
| 検索キーワード | 空欄 |
| カテゴリ | すべて |
| 表示件数 | 30件 |
| URLクエリ | なし |

### 5.6 対象外の機能

今回の必須要件には、以下を含めない。

- 商品の新規登録・編集・削除
- ユーザーログイン・認証
- データベースへの保存
- 購入・決済機能

## 7. データ設計・処理構造

### 7.1 データ設計

商品データは `public/products.json` に保存する。

- データ形式：JSON配列
- 商品件数：30件
- カテゴリ：5種類、各6件
- 商品ID：1〜30の一意の整数
- データ：学習用の架空の商品情報

商品1件の構造：

```json
{
  "id": 1,
  "name": "ノートパソコン 14インチ",
  "category": "pc",
  "price": 89800,
  "stock": 12
}
```

### 7.2 カテゴリの識別子

JSONには英語の識別子を保存し、画面には日本語の表示名を使用する。

| 識別子 | 表示名 | 件数 |
|---|---|---|
| pc | パソコン | 6 |
| accessories | PC周辺機器 | 6 |
| smartphone | スマートフォン | 6 |
| audio | オーディオ | 6 |
| appliances | 家電 | 6 |

カテゴリの絞り込みとURLクエリには英語の識別子を使用する。

### 7.3 データ取得の流れ

1. アプリの画面を開く。
2. `fetch()` で `/products.json` を取得する。
3. JSONをJavaScriptの配列として読み込む。
4. 商品データをReactで管理する。
5. 検索条件に一致する商品を抽出する。
6. 商品名・カテゴリ・価格・在庫数をテーブル表示する。

取得失敗時はエラーを表示し、再試行できるようにする。

### 7.4 検索・絞り込みの処理

商品名検索は部分一致とする。

カテゴリ絞り込みは識別子の完全一致とする。

AND検索を使用し、両方の条件を満たす商品のみ表示する。

初期状態は検索条件なしで、30件すべてを表示する。

検索結果の表示順序はJSONの順序を保持する。

### 7.5 URLクエリの管理

検索キーワードは `q`、カテゴリは `category` で管理する。

例：

`/?q=マウス&category=accessories`

操作時に検索結果とURLを即時更新する。

ページを再読み込みした場合はURLから検索条件を復元する。

クリアボタンは `q` のみを削除する。

検索条件リセットボタンは `q` と `category` の両方を削除する。

### 7.9 コンポーネント設計

親コンポーネント ProductSearch.tsx で商品データ・検索キーワード・カテゴリ・読み込み状態・エラー状態を管理する。

子コンポーネントにはpropsを使って必要なデータと操作用の関数を渡す。

- SearchForm.tsx：検索キーワードの表示・入力・クリア
- CategoryFilter.tsx：カテゴリの表示・選択
- ProductTable.tsx：絞り込み済み商品一覧の表示

検索ロジックはlib/products.tsに分離する。商品データの型はtypes/product.tsに定義する。

app/page.tsxはServer Componentとし、ProductSearch.tsxをClient Componentとして使用する。useSearchParamsを利用する部分はSuspenseで囲む。

URL更新にはwindow.history.replaceStateを使用する設計とする。実装後にリアルタイム検索の応答速度とURL復元を検証する。


### Reactのpropsと検索フォーム

- props：親コンポーネントから子コンポーネントに渡す情報
- onChange：入力内容が変わったときに実行する処理
- onClick：クリックされたときに実行する処理
- onQueryChange：検索文字の変更を親へ伝える関数
- Controlled Component：親の状態によって入力欄の値を管理する方式

SearchForm.tsxは検索文字の入力とクリアだけを担当する。
検索データの管理や絞り込み処理は親コンポーネントに任せる。
